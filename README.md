# AI 서비스 버그 찾기 (Bug Bash)

**AI 품질검증 특강 2일차 7교시** 실습 저장소입니다. 코드는 없습니다. 화면과 명세를 비교해 결함을 찾고, **이슈(Issue)로 보고**합니다.

## 준비물

- GitHub 계정 (로그인만 하면 누구나 이 저장소에 이슈를 등록할 수 있습니다)
- [요구사항 명세](requirements.md) — 버그는 "명세와 다른 것"입니다

## 오늘의 대상: 가상 서비스 화면 4장

| 화면 | 설명 |
| --- | --- |
| [① 판정 결과 (대상)](screens/01-result-eligible.png) | 입력: 만 18세, 거주 12개월, 미취업 |
| [② 판정 결과 (비대상)](screens/02-result-not-eligible.png) | 입력: 만 25세, 거주 3개월, 미취업 |
| [③ 정보 입력 오류](screens/03-input-error.png) | 입력: 나이 -1 |
| [④ 운영 대시보드](screens/04-dashboard.png) | 암 진단 보조 AI 성능 |

여기에 **오전 실습 노트북에서 찾은 결함**(테스트 케이스 표의 ❌, 손 계산과 다른 도구 결과)도 함께 보고합니다.

## 진행 순서 (팀별)

1. **찾기 (15분)**: 화면을 명세(R-01 ~ R-24)와 한 줄씩 비교합니다. 의심되는 곳을 모두 메모합니다.
2. **보고 (20분)**: [Issues → New issue → 버그 리포트](https://github.com/leejaehee1/ai-quality-bug-bash/issues/new/choose) 양식으로 결함 1개당 이슈 1개를 등록합니다.
   - 제목 앞에 팀 이름을 붙입니다. 예: `[A팀] 만 18세를 지원 대상으로 판정함`
   - 화면 캡처는 입력 칸에 **이미지를 끌어다 놓으면** 첨부됩니다.
3. **분류 (10분)**: 다른 팀 이슈를 읽고 **중복**이면 댓글로 알려 줍니다. 심각도·우선순위가 적절한지 의견을 남깁니다.
4. **발표 (8교시)**: 가장 심각한 결함 1개와 그 이유를 발표합니다.

## 좋은 버그 리포트의 조건

- **재현 가능**: 누가 읽어도 같은 결함을 다시 볼 수 있다 (입력값을 정확히)
- **근거가 있다**: 어떤 요구사항(R-xx)과 다른지 적는다
- **하나에 하나**: 결함 1개 = 이슈 1개
- **사실과 추측을 나눈다**: 본 것과 짐작한 원인을 따로 적는다
- **감정이 없다**: "이상해요", "엉망이에요" 대신 기대 결과와 실제 결과

> 이 저장소는 공개 저장소입니다. 이슈에 이름, 연락처 같은 개인 정보를 적지 마세요.
